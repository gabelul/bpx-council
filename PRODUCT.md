# Product

## Register

product

## Users

Developers and coding-agent users configuring a standalone advisor/council CLI.
Gabi builds and tests this in a terminal; navigation must work without a mouse.

## Product Purpose

Set up advisor backends, models and effort; assign Council/Debate routes; manage
personas; explicitly test connections. Inspect a staged draft, then save once or
discard without changing files. Preserve non-interactive CLI behavior.

## Brand Personality

Hands-on, direct, playful. A DOS/Turbo Vision workbench, explicitly chosen by Gabi,
with enough visual structure to make complex settings easy to find.

## Anti-references

Huge blue terminal sheet with a tiny status log stranded at upper left. Generic
web-dashboard cards, neon effects, decorative gradients, mouse-only controls.
Permanent login warnings masquerading as actual connection-test results.

## Design Principles

- Use the approved centered dialog prototype as the visual anchor across settings.
- Keep context and current keyboard focus visible; use nested detail screens.
- Presentation changes must not change staged saves, trust or paid-call boundaries.
- Distinguish local installation/version facts from exact route-test receipts.
- Fit the terminal rather than letting empty space stretch every field.

## Accessibility & Inclusion

Keyboard-first focus/navigation and cancellation. Respect nonempty NO_COLOR even
under FORCE_COLOR. Status and focus need text markers, not color alone. Unicode
terminal-cell measurement, narrow layouts and live resize must keep active rows,
confirmation actions and safety warnings reachable. This is terminal software;
no browser WCAG conformance claim is made.
